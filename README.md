# Reel Harvester

## Локальная UI-панель

Обычный запуск в Windows — двойной клик по `START_REEL_HARVESTER.bat`. Он
одновременно запускает локальный сервер и открывает UI в обычном Chrome.
При старте сбора Playwright открывает отдельное окно установленного Chrome с
постоянным Instagram-профилем `.instagram-profile`, а после операции закрывает
только это рабочее окно. Авторизованная сессия между запусками сохраняется.

Альтернативный запуск из терминала:

```powershell
npm.cmd run desktop
```

Откройте `http://127.0.0.1:4173`. Панель показывает статистику и библиотеку,
запускает сбор, анализ и Whisper, выводит живые логи и экспортирует CSV. У каждого
рилса показываются точные дата и время публикации и относительный возраст записи,
например «3 недели назад».
Сервер слушает только localhost и не публикует данные в интернет.

Локальный сборщик метаданных публичных Instagram Reels без Instagram API и
Apify API. Он управляет установленным Chrome или Edge через `playwright-core`,
использует устойчивые локаторы и auto-wait, выполняет реальные клики, движения
мыши и прокрутку колёсиком, слушает сетевые запросы и читает DOM страницы.
Отдельный Chromium не скачивается.

## Важные ограничения

Абсолютно неограниченного и неблокируемого парсинга не существует. Instagram
может менять вёрстку, вводить rate limit или показывать checkpoint. Проект не
обходит CAPTCHA, не подменяет fingerprint, не ротирует украденные сессии и не
пытается скрыть автоматизацию. При обнаружении checkpoint сбор останавливается,
а состояние сохраняется в SQLite.

Используйте проект только для данных, которые вы вправе собирать, соблюдая
условия Instagram, права авторов и применимое законодательство. Не публикуйте
файл профиля браузера: в нём находится ваша авторизованная сессия.

## Установка

Требуется Node.js 22.5 или новее.

```powershell
npm.cmd install
Copy-Item config.example.json config.json
```

Нужен установленный Chrome или Edge. Если браузер расположен нестандартно,
задайте полный путь в переменной окружения `CHROME_PATH`.

Первый вход выполняется вручную:

```powershell
npm.cmd run login
```

После успешного входа и появления ленты нажмите Enter в терминале. Сессия
останется в `.instagram-profile`.

## Сбор

Источником может быть страница Reels профиля, хэштег, страница поиска или прямая
ссылка на Reel:

```powershell
npm.cmd run collect -- https://www.instagram.com/natgeo/reels/ --max=50
npm.cmd run collect -- https://www.instagram.com/reel/SHORTCODE/
```

По умолчанию работает быстрый режим: сборщик прокручивает только сетку Reels и
не открывает каждый рилс. Он сохраняет shortcode, URL, CDN-ссылку на превью,
доступный на карточке счётчик и описание из `alt`/accessibility-атрибутов, когда
Instagram его предоставляет. Для гарантированно более полной подписи, даты,
лайков, комментариев и CDN-ссылки видео используйте `--enrich` — этот режим
открывает каждый рилс:

```powershell
npm.cmd run collect -- https://www.instagram.com/natgeo/reels/ --max=50 --enrich
```

Для загрузки самих видео добавьте `--download`; этот флаг также включает
открытие каждого рилса. Убедитесь, что у вас есть право сохранять контент:

```powershell
npm.cmd run collect -- https://www.instagram.com/natgeo/reels/ --download
```

Повторный запуск пропускает уже сохранённые shortcode. Скорость и число
прокруток задаются в `config.json`. Не уменьшайте задержки: это повышает риск
ограничения аккаунта.

## Результаты

Данные находятся в `data/reels.sqlite`. Экспорт:

```powershell
npm.cmd run export -- --out=data/reels.csv
npm.cmd run export -- --out=data/reels.jsonl
npm.cmd run stats
```

## Скролл Reels-ленты

В дашборде есть отдельная операция «Скролл Reels». Playwright открывает общую
Reels-ленту, кликает активный плеер, задерживается на каждом видео заданное число
секунд и переходит дальше настоящей прокруткой колёсиком. Каждый запуск хранится
как отдельная сессия со списком увиденных аккаунтов и рилсов.

Из терминала тот же режим запускается так:

```powershell
npm.cmd run scroll -- --count=20 --watch-min=3 --watch-max=7
```

Для каждого увиденного рилса сохраняются дата публикации, просмотры, лайки,
комментарии, репосты и отправки. Звук, ссылка на аудио и статистика трека в этом
режиме намеренно не собираются. Дашборд рассчитывает engagement как
`лайки / просмотры` и присваивает грейды:

- просмотры: до 100K, 100K+, 500K+ и 1M+;
- engagement: ниже 2%, 2%+, 5%+ и 10%+;
- свежесть: за сутки, до 7 дней, до 30 дней и старше месяца.

Отдельный фильтр показывает свежие ролики младше 30 дней, которые уже набрали
не менее 100 тысяч просмотров.

Повторный локальный анализ уже сохранённых описаний не открывает Instagram:

```powershell
npm.cmd run analyze
```

Основные поля: автор, подпись, точные дата и время публикации, просмотры, лайки, комментарии, URL видео,
репосты, отправки, обложка, источник и время сбора. Полный режим объединяет
просмотры из сетки аккаунта со счётчиками на странице рилса. Если Instagram
показывает кнопку действия без публичного числа (например, «Поделиться»), поле
остаётся пустым, а не подменяется нулём. Доступность отдельных полей зависит от
текущей вёрстки Instagram и прав вошедшего пользователя.

Быстрый режим также сохраняет хэштеги, упоминания, внешние ссылки, язык, эмодзи,
ключевые слова, темы, рекламные маркеры, число слов и символов, похожие описания,
позицию в сетке, закрепление, тип карточки, размеры/варианты превью и, когда эти
данные есть в DOM, лайки, комментарии, длительность, аудио, соавторов и ремиксы.

Во время работы подробный прогресс выводится в терминал и одновременно
записывается в `data/collector.log`. Если после запуска больше 20 секунд нет
новой строки, последняя операция и возможная ошибка останутся в этом файле.
При ошибке Playwright дополнительно сохраняет trace со скриншотами, DOM-снимками
и действиями в `data/traces/*.zip`; его можно открыть командой
`npm.cmd run trace -- <путь-к-zip>`.

## Предоценка звука до расшифровки

Полный сбор (`--enrich`) сохраняет название звука, исполнителя, Instagram audio
ID и прямую ссылку вида `https://www.instagram.com/reels/audio/.../`. Эта ссылка
открывает все рилсы, использующие тот же звук.

Библиотека делит записи на «речь подтверждена», «вероятна речь», «музыкальный
трек», «вирусный оригинальный звук», «речи не найдено» и «нужно проверить».
При полном сборе страница каждого звука проверяется отдельно, поэтому у
музыкальных треков в библиотеке тоже показывается количество созданных Reels.
Если на странице оригинального аудио найдено больше 10 разных рилсов, звук
попадает в вирусную категорию. Это
не считается автоматически песней или речью — источником может быть цитата,
мем, зацикленный фрагмент или музыка. Сборщик сначала читает готовый счётчик
Instagram (например, `5,3 тыс. видео Reels`), а прокрутку сетки использует только
как запасной вариант. Именованный общий трек имеет
приоритет над текстом Whisper, потому что распознавание вокала не означает, что
в ролике говорит автор. Для оригинального аудио без прошлой проверки выводится
осторожная рекомендация расшифровать; после Whisper результат уточняется.

Фильтр «Смысл расшифровки» показывает только ещё не расшифрованные рекомендованные
записи, музыку или неопределённые случаи. Кнопка «Выбрать рекомендованные» отмечает
именно текущие нерасшифрованные карточки и передаёт Whisper их точные shortcode.

## Локальная расшифровка речи

Один раз установите изолированную Python-среду, `faster-whisper` и `yt-dlp`:

```powershell
npm.cmd run setup:transcribe
```

Транскрайбер сам получает реальный аудиофайл по сохранённой ссылке рилса через
`yt-dlp`, поэтому предварительно открывать каждый рилс с `--enrich --download`
больше не нужно. Достаточно собрать быстрый список и запустить расшифровку:

Если при полном сборе Instagram показывает видео только как `blob:`/MediaSource,
сборщик сохраняет карточку и метаданные без локального файла. Это не считается
ошибкой: файл будет получен через `yt-dlp` непосредственно перед расшифровкой.

```powershell
npm.cmd run collect -- https://www.instagram.com/natgeo/reels/ --max=50
npm.cmd run transcribe -- --model=small --limit=50
```

В локальной панели можно отметить галочками конкретные карточки в библиотеке и
нажать «Расшифровать выбранные». Такой запуск передаёт Whisper точный список
shortcode, сохраняет выбор при переключении фильтров и не захватывает остальные
записи из общей очереди. Для ручного запуска доступен тот же режим:

```powershell
npm.cmd run transcribe -- --model=small --shortcodes=ABC123,XYZ789
```

По умолчанию используется CPU `int8`, VAD, `beam_size=1` и модель `small`.
Модель скачивается один раз в `data/models`. Текст, язык, вероятность и сегменты
с таймкодами сохраняются в SQLite. Повторный запуск продолжает очередь, а
одинаковые медиафайлы определяются по SHA-256 и не расшифровываются повторно.
Если в базе сохранён временный `blob:` URL или URL отсутствует, транскрайбер
получает свежую ссылку по публичной странице рилса. Для контента, требующего входа,
он повторяет попытку с cookies из `.instagram-profile`.

Дополнительные параметры:

```powershell
npm.cmd run transcribe -- --model=base --limit=10
npm.cmd run transcribe -- --language=ru --word-timestamps
npm.cmd run transcribe -- --force --limit=1
```
